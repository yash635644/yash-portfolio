Plain static site: every page is a flat `.html` file, no folders and no build step needed to deploy. Push to GitHub Pages and it's live.

The service pages and blog are generated by scripts kept **outside** this repo in `../site-tools/` (`build-site.js`, `content-services.js`, `content-blog.js`, `set-domain.js`). Edit the content files, then run `node site-tools/build-site.js` from the parent folder: it rebuilds every generated page, the services dropdown and latest articles on the home page, and `sitemap.xml`. Run `node site-tools/audit.js` before publishing to check titles, descriptions, canonicals, schema, headings, links and the sitemap.

## Moving to a custom domain

1. Buy the domain (e.g. `yashtrivedi.in`).
2. From the parent folder run `node site-tools/set-domain.js yashtrivedi.in`, then push all changed files plus the new `CNAME` file.
3. At your domain registrar, add these DNS records:

   | Type | Name | Value |
   |---|---|---|
   | A | @ | 185.199.108.153 |
   | A | @ | 185.199.109.153 |
   | A | @ | 185.199.110.153 |
   | A | @ | 185.199.111.153 |
   | AAAA | @ | 2606:50c0:8000::153 |
   | AAAA | @ | 2606:50c0:8001::153 |
   | AAAA | @ | 2606:50c0:8002::153 |
   | AAAA | @ | 2606:50c0:8003::153 |
   | CNAME | www | yash635644.github.io |

4. In the GitHub repo: **Settings → Pages → Custom domain**, enter the domain, wait for the DNS check, then tick **Enforce HTTPS**.
5. Old `github.io` links redirect to the new domain automatically.
6. Add the domain as a **Domain property** in Google Search Console and in Bing Webmaster Tools, and submit `sitemap.xml` in both.
7. Update the website link on LinkedIn, GitHub, Google Business Profile and any directory listings.
8. Regenerate `og-image.jpg` so the share card shows the new address.
